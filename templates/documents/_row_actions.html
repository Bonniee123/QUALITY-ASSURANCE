{% comment %} One menu per row instead of five loose icons. Five 32px chips plus their gaps took ~176px of every row, on tables that are already wide enough to scroll sideways; the eye also had to decode five glyphs per row, 22 rows at a time, with the meaning carried only by colour and a tooltip. A single kebab gives the width back to the columns that hold the reading matter, and the menu labels each action in words. Nothing about the actions themselves changes: the same URLs, the same `js-qa-*` hooks the panels and the delete modal already listen for, and the same two permission conditions the Repository has always used -- Admin and QA Head may edit and delete anything, Faculty only their own uploads. The server enforces that independently in `user_can_modify_document`. `data-bs-popper-config` pins the menu with position:fixed so it is not cut off by the `overflow` on `.table-responsive`; without it the last rows' menus were clipped by the panel edge. No `title` on the toggle. The column header says "Actions" in the open, on every row at once, so a tooltip repeated it one row at a time and only for someone using a mouse. `aria-label` stays: it is the button's accessible name, not a tooltip, and an icon-only control has to carry one. {% endcomment %}
